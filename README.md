# Claude Team 续费登记系统

用于登记 Team 成员的**用户名 / 邮箱 / 每月续费日 / 续费价格**，支持：

1. 手动维护续费日与价格  
2. 定期从 Claude 导出（`users.json` 或整个导出目录）**同步补充成员**  
3. 不定期标记**当月已续费**  
4. 看板按续费日 / 价格 / 当月缴费排序，以及盈利 / 不续费损失汇总

## 计费与财务规则（当前实现）

本系统是**人工缴费登记 + 席位毛利估算 + 不续费损失台账**，不会自动向用户扣款，也不会自动向 Claude 付款。以下以当前 `server.py`、`renewal_cli.py`、`finance_metrics.py`、`nonrenewal_loss.py` 和 `index.html` 为准。

### 1. 售价、成本与档位

| 项目 | 规则 |
|---|---|
| 成员售价 `price` | 每月向成员收取的人民币价格，人工设置；允许 0 或留空，不允许负数、NaN、无穷大 |
| 标准席位 | `price < 800`：月成本 **$27 × 6.8 = ¥183.60** |
| 高级席位 | `price ≥ 800`：月成本 **$127 × 6.8 = ¥863.60**；恰好 800 归高级 |
| 汇率 | 固定 **1 USD = 6.8 CNY**，不自动获取实时汇率 |
| 档位判断 | 依据当前登记售价，不读取 Claude 实际订阅档位；售价留空不视为零成本 |
| 实收金额 `payments[].amount` | 独立于售价；标记已缴时未指定实收金额，使用当时的 `price` |

售价低于席位成本时，盈利可以为负，不截断为 0。调整售价可能改变成本档位，并影响之后的盈利估算和删除预估；**已入账删除损失不随售价或汇率规则变化而重算**。

### 2. 两种账单日与日期口径

| 字段 | 对应对象 | 用途 |
|---|---|---|
| 成员 `billing_day` | 用户自己的每月续费日，1–31 或留空 | 单日盈利的可计算条件、周期盈利、总累计盈利起点、续费提醒 |
| 域名目录 `billing_day` | Claude Team 的每月预付账单日，1–31 或留空 | 预计删除损失与实际删除损失的 Team 成本周期 |
| `activation_date` | 手工登记的开通日期 | 仅展示，不参与上述财务公式，也不作为历史盈利起点 |

两个账单日互不覆盖。月内没有所填日期时压到该月最后一天，例如 31 号遇非闰年二月按 28 号，闰年按 29 号。

服务端盈利汇总和删除结算使用 **Asia/Shanghai（北京时间）日历日期**；时间戳通常保存为 UTC。删除预估也显式使用上海日期。当前网页的成员盈利行、默认月份和续费提醒使用浏览器本地日期：浏览器位于其他时区时，跨日附近可能与服务端汇总不同；应以服务端结算日期为准。

### 3. 缴费登记、月份与提醒

- 按 `YYYY-MM` 登记已缴状态；网页“一键切换”作用于工具栏所选月份，不根据实际支付日期自动推导月份。
- 新增成员默认未缴；有该月 `paid=true` 记录才算该月已缴。其他月份已缴不代表本月已缴。
- 标记已缴会新增或更新该月记录，保存实收金额、备注和登记时间。取消已缴会移除该月份记录，不会自动办理退款。
- 修改当前售价不会直接改写已有缴费金额；再次标记某月已缴会按此次提交金额（未指定则当前售价）更新该月记录。
- **已缴/未缴不是盈利计算开关**：未缴但价格和续费日有效的在册成员仍可计算盈利。实际付款晚于续费日，不平移周期；实收金额不替代售价进入盈利或删除成本公式。
- “最近已缴月”取已缴记录中最大的月份，不是最后一次操作日期。
- 提醒取成员下一次续费日，距离今天 **0–7 天（含今天、含第 7 天）**且对应续费月份未缴才显示；已缴该月份后移出提醒。缺续费日或 `inactive` 成员不提醒，Team 账单日不用于用户提醒。
- 工具栏月份、搜索和缴费筛选只影响列表及相应人数，不把顶部财务 KPI 改为该月收支报表。

### 4. 单日盈利

对每名可计算成员：

```text
月毛利 = 当前售价 − 当前席位月成本
单日盈利 = 月毛利 / 30
全站单日盈利 = 所有可计算成员单日盈利之和
```

**分母固定 30**，不随月份长短变化。当前实现要求价格有效且成员续费日已设置，即使单日公式本身不含续费日，缺续费日也不计入汇总。

### 5. 周期盈利与表格“累计盈利”

```text
周期起点 = 今天或今天之前最近一次成员续费日（短月压月末）
实际已用天数 = 今天 − 周期起点 + 1
计盈天数 = min(实际已用天数, 30)
成员周期盈利 = 单日盈利 × 计盈天数
全站周期盈利 = 所有可计算成员周期盈利之和
```

- 续费日当天计第 1 天，而不是 0 天；到下个续费日重新从第 1 天计算。
- 每人独立周期，不在自然月 1 号统一清零。
- 31 天周期最多计 30 天；短周期只按实际经过天数计，不补足到 30 天。
- 表格“累计盈利”就是该成员的**本周期盈利**，不是该成员终身盈利。

### 6. 总累计盈利（跨周期估算）

```text
历史起点 = 将历史锚点回推到其所在的成员续费周期起点
历史天数 = max(0, 今天 − 历史起点 + 1)
成员历史盈利 = 当前单日盈利 × 历史天数
全站总累计盈利 = 当前所有可计算成员的历史盈利之和
```

历史锚点按实际代码确定：

1. 先读取有效 `created_at`；同时查找所有缴费记录中最早的有效 `recorded_at`。
2. 若最早缴费登记时间早于 `created_at`，取更早的登记时间；没有 `created_at` 则用最早登记时间。
3. 两者都不存在时，直接以当前成员续费周期起点为历史起点。
4. 未来锚点压到今天；历史计算设有 **2024-01-01** 下限，回推后的起点也不早于该日期。

**本项不设 30 天总上限**，跨周期按连续日历天数累计，不是把各期封顶后的周期盈利相加。它不是现金实收、不是固定历史账本：历史部分按当前售价和当前成本回溯，改价、改续费日或改变历史锚点都可能改变结果。

**特别注意：删除成员后，该成员从三个盈利指标的计算集合中移除，其历史贡献也不再出现在“总累计盈利”里。** 该行为沿用原系统；新功能只永久保留删除损失，没有新增永久利润流水。

### 7. 预计删除损失（在册成员预览）

背景：Team 账单日已预付成员未来一个月的席位费，成员中途不续费退出后，剩余预付成本由管理员承担。

```text
Team 周期起点 = 删除日当天或之前最近一次 Team 账单日
Team 周期终点 = 下一个 Team 账单日（结束日不含）
实际周期天数 = 周期终点 − 周期起点
剩余天数 = 周期终点 − 删除日
预计删除损失 = 席位月成本 × 剩余天数 / 实际周期天数
```

- 这里的分母是 **Team 周期实际天数**，可能为 28、29、30、31，不能套用盈利固定 `/30`。
- 删除当天计损失，下一个 Team 账单日不计入当前周期；按日期而非小时折算。
- **恰在 Team 账单日删除，视为新一期已预付，计完整月成本。** 账单日前一天删除仅计当前周期剩余 1 天。
- 表格仅显示“若现在删除”的预估，随日期、售价和 Team 账单日变化；它不等于已发生损失，也不会提前计入顶部合计。
- 不需要成员个人续费日，但必须有有效售价和 Team 账单日；缺项时显示无法计算并阻止删除，不能默认为 ¥0。

### 8. 不续费损失合计（永久台账）

- 自功能启用后，每次成功删除成员，按服务器删除时的日期、售价档位和 Team 账单日计算并固定一笔损失。
- **不追溯功能启用前的删除，不把原“应退金额”转换为期初损失。** 启用时间读取 `data/nonrenewal_loss.json` 的 `enabled_at`；首次启用余额为零，重复启用不清零、不重置起算时间。
- HTTP 删除与 CLI `remove` 使用同一规则；当前没有删除原因分类，**任何正常成员删除（包括手工清理）都会计损失**，不是只有“未缴”成员才计。
- 每笔按人民币分使用 Decimal **四舍五入（ROUND_HALF_UP）**，先把单笔金额固定为两位小数，再精确求和。
- 终身累计、不按自然月或账单周期清零，不随时间减少。后续改价、改账单日不修改旧记录；重复请求删除已不存在的成员不会再次记账。
- 同一身份重新导入/添加后又真正删除，属于新的一次删除，会新增损失，系统没有“复用席位自动冲销旧损失”功能。
- 点击顶部“不续费损失合计”可查域名、成员、删除时间、上海日期、成本档位、账单周期、剩余天数与结算金额。
- 成员移除后损失记录独立保留；域名改名/删除也保留已有损失。域名整体清空不是逐个成员删除，不会替所有被清空成员自动补记新损失。
- **损失与三个盈利指标分开展示，不额外从单日、周期或总累计盈利中扣除。** 删除成员本身仍按上一节所述改变在册成员集合。

### 9. 计算范围、精度、刷新与缺项

| 项目 | 当前规则 |
|---|---|
| 顶部三个盈利 KPI | 所有实时域名中，非 `inactive` 且价格/成员续费日有效的成员之和；`missing_in_export` 不等于停用，仍可参与计算 |
| 资料缺失 | 盈利行显示 `—`、不加入可计算盈利合计；缺售价或 Team 账单日不能结算删除损失 |
| 盈利精度 | 内部按原始小数累加；服务端汇总保留 4 位小数，网页显示 2 位；逐行显示值相加可能有尾差 |
| 删除损失精度 | 每笔先四舍五入到分再累计，API 金额为两位小数字符串 |
| 顶部刷新 | 服务启动、每小时整点、成员保存后的合并刷新、手动强制刷新；CLI 删除等文件变化也会触发损失对账 |
| 普通缓存读取 | 文件版本未变化时读取缓存，不在浏览器全站扫描成员；因此页面短时间可能显示上一批缓存 |
| 删除异常恢复 | 成员删除和损失明细先写入同一成员文件，再同步独立台账；根台账同步失败会提示已删除、待同步，后续对账恢复，不应重复删除 |

### 10. 算例（均为虚构数据）

| 场景 | 计算 | 结果 |
|---|---|---|
| 售价 ¥260，成员续费日 8 号，今天 2026-09-12 | 标准成本 ¥183.60；日毛利 `(260−183.60)/30`；本期从 9 月 8 日起含当天共 5 天 | 单日约 **¥2.55**，周期 **¥12.73** |
| 上述成员 `created_at=2026-07-10`，无缴费记录 | 历史起点回推至 7 月 8 日，至 9 月 12 日含两端共 67 天；按未取整日毛利乘 67 | 总累计贡献 **¥170.63** |
| 售价 ¥260，Team 账单日 9 号，2026-09-12 删除 | Team 周期 `[2026-09-09, 2026-10-09)`，30 天，剩余 27 天；`183.60×27/30` | 删除损失 **¥165.24** |
| 售价 ¥800，Team 账单日 31 号，2026-02-27 删除 | 周期 `[2026-01-31, 2026-02-28)`，28 天，剩余 1 天；`863.60×1/28` | 删除损失 **¥30.84** |
| 上述高级成员改在 2026-02-28 删除 | 进入 `[2026-02-28, 2026-03-31)` 新周期，剩余天数等于全部周期天数 | 删除损失 **¥863.60** |

### 11. 已废止的展示与数据维护边界

- “应退金额合计”和成员“应退金额”已由不续费损失合计、预计删除损失替代；不要将旧的客户退款参考公式与预付成本损失混用。
- “封号·单日 / 封号·累计”不再展示，顶部仅保留四项 KPI。
- Claude 导出导入用于同步成员身份，不证明已付款；已有成员的价格、个人续费日和缴费记录保留。新导入成员只在设置了默认值时继承默认日/价，默认未缴。
- `defaults --apply` 只为相应值为 `None` 的成员填入所提供默认日/价，不覆盖已设置字段；不加 `--apply` 仅保存默认值。
- 本章节记录现有估算口径，不代表 Claude 官方账单、税费核算或自动付款对账。台账恢复与部署操作详见 [不续费损失维护说明](docs/nonrenewal-loss.md)。

## 快速开始

```bash
cd /root/workspace/renewal-registry

# 看板（终端）
python3 renewal_cli.py board

# 列表
python3 renewal_cli.py list

# 给成员填续费日与价格
python3 renewal_cli.py set CHUJUN --day 8 --price 100
python3 renewal_cli.py set moshaobo --day 10 --price 80

# 批量默认值并填充空字段
python3 renewal_cli.py defaults --day 1 --price 100 --apply

# 标记 2026-07 已续费
python3 renewal_cli.py paid 2026-07 CHUJUN moshaobo Shirley --note 微信

# 查看未缴
python3 renewal_cli.py unpaid 2026-07

# 从 Claude 导出同步新成员（zip / 目录 / users.json 均可）
python3 renewal_cli.py sync /path/to/data-...-batch-0000.zip
python3 renewal_cli.py sync /path/to/data-...-batch-0000
python3 renewal_cli.py sync /path/to/users.json --mark-missing

# 删除成员（永久，同时结算损失；需启用账本、设置 Team 账单日与成员价格）
python3 renewal_cli.py remove ash yuyu

# 导出 CSV
python3 renewal_cli.py export-csv
```

## 网页看板

```bash
cd /root/workspace/renewal-registry
python3 server.py
# http://127.0.0.1:8765/
```

看板顶部 **「导入导出包」** 可直接选 Claude 下载的 `.zip`（或单独 `users.json`），会调用 `POST /api/sync-export` 自动合并成员，**保留**已有续费日/价格/缴费记录。请通过 `server.py` / systemd 访问以支持写入。

智能分域规则：明确命中实时 Team 域的邮箱按自身后缀分域；Gmail、Outlook 等公共/共享邮箱继承整个导出包的所属 Team 域。若自动导入时发现唯一且格式合法的 `admin@新域名`，系统会先在 8765/8766 同时创建该域空壳，再把包导入新域。多个不同的 `admin@域名` 会拒绝导入，避免错误建域。已有域的包所属域优先由 `admin@<实时域>` 判断，其次使用文件名中的域名，再其次使用包内实时域邮箱的多数票。

表头可点 **续费日 / 价格 / 当月缴费** 排序（互斥）。

## 字段说明

| 字段 | 含义 |
|---|---|
| `username` / `email` | 成员名与邮箱 |
| 成员 `billing_day` | 用户每月续费日（1–31），参与盈利周期与提醒 |
| 域名目录 `billing_day` | Team 每月预付账单日（1–31），用于删除损失周期 |
| `activation_date` | 开通日期，仅展示 |
| `created_at` | 成员录入时间，参与历史盈利锚点选择 |
| `price` | 续费价格（手动填） |
| `payments[]` | 按月缴费记录：`{month, paid, amount, note, recorded_at}` |
| `loss_events[]` | 成员文件中的删除损失持久化明细，用于独立台账同步与恢复 |

> 运行数据和成员隐私文件不纳入版本库；请勿将真实数据作为测试夹具。
